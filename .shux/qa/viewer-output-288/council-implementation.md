# Implementation council (codex, agy) on d36b738..fb88e28, 2026-11-23

**FIX before merge.** Both reviewers agree that issue #288’s `--plain` guarantee breaks outside the main renderer, and the VT QA gate fails because the required evidence is missing.

### Merge blockers

1. **P1 · Plain rendering leaks hidden controls during selection and copy mode.** Codex reproduced U+202E in the output when the copy cursor repainted a cell. Source inspection confirmed the same bypass in scrolled history and selection highlighting, including normal-mode mouse selection. Use one plain-text rendering policy across these paths and `render_full`, preserving cell width, concealed text, and intentional shaping characters. Define which hidden controls plain mode strips and cover that set in tests. The existing title sanitizer serves a different purpose. [Copy-mode renderer] · [Selection rendering] · [Full renderer]
2. **P1 · Plain attach emits OSC 52 clipboard writes.** Keyboard yank, copy-mode drag release, normal-mode drag release, and context-menu Copy all reach clipboard emission. Normal drag release is the strongest case because selecting text implicitly requests a host clipboard write. Whether the clipboard changes depends on the host terminal. For #288, suppress OSC 52 through one daemon-side check, make unavailable copy actions clear, and show the copied confirmation only when a write was sent. [Keyboard yank] · [Copy-mode drag] · [Live selection and menu copy]
3. **P2 · Plain teardown changes the host cursor.** Detach and signal cleanup emit cursor shape and colour resets. The panic hook does the same and is installed before negotiation. Gate those resets on whether an active attach used non-plain mode, while preserving the terminal cleanup required on every exit path. [Terminal cleanup] · [Panic cleanup]
4. **P2 · Cursor elision can write onto the wrong row during resize.** Replay confirmed that a five-column frame can wrap onto the next row when the host has already shrunk to four columns. Test mismatched widths, including the bottom status row. Disabling autowrap during drawing may preserve the bandwidth gain if terminal-mode restoration and replay both pass. Explicit positioning is the fallback. [Cursor tracking]
5. **Required VT QA evidence is missing.** Both reviewers observed the gate fail. Complete the pregate, run VT neutrality against `d36b738`, and record the required solid QA and council evidence before rerunning `check-vt-qa`. [VT QA requirements]

### Compatibility and follow-up

- **Old-daemon refusal can mutate session state.** The client refuses before taking over the host terminal, but the old daemon may already have created a session or resized panes. Reject unsupported plain attaches before those operations. A plain-only protocol bump is a concrete option to verify against an old daemon while keeping protocol 1 for normal attaches. [Daemon protocol check] · [Client refusal]
- **OSC 8 lifecycle needs an explicit compatibility decision.** Cursor restore can revive a closed link, and alternate-screen transitions can carry an open link across buffers. Both behaviors predate #288, but preserving links through SGR 0 makes the screen-switch carryover easier to encounter. Pin the intended behavior for save and restore and for `47`, `1047`, and `1049`. Track DECSTR as a full soft-reset change. Its current tab-stop test passes when the command is ignored. [Saved cursor] · [Screen switches] · [DECSTR test]
- **Lower-priority hardening.** Validate raw-client prefix and copy-search text before measuring or drawing it. The reviewed paths reflect input to the same connection. Skip graphics probing for plain clients. Runtime Kitty disable can emit placement deletes after an earlier graphics frame, while fresh plain attaches begin with no placements. The proposed `u16::MAX` cursor-tracking fix misses the earlier overflow in `MoveTo`, and normal attach dimensions stay well below that limit. [Prefix formatting] · [Search input] · [Graphics probe] · [Kitty emitter]
