# Design council (codex, agy, grok) on the sharing-groundwork proposal, 2026-11-22

Ārya, **verdict: RETHINK Proposal v1.** Land **#190 PR A → #191 → local client listing and detach**. Keep #190’s viewport follow-ups moving in parallel with #191. Defer delegated sharing until there’s a concrete consumer and an explicit broker trust model. Drop PTY-authored approval replies and raw keystroke recording from the roadmap.

This synthesizes the source reviews of `d36b738` (`v0.57.3`). The spike timings, RSS, and byte counts were reported and were not independently reproduced. [Proposal] · [#190](https://github.com/indrasvat/shux/issues/190) · [#191](https://github.com/indrasvat/shux/issues/191)

## Decisions for the redesign

| Area | Decision |
|---|---|
| **Broker authority** | Treat a broker with access to the owner’s Unix sockets as owner-trusted. A restricted connection can enforce what visitor frames may do and limit accidental forwarding. Containing the broker itself requires OS isolation from owner sockets and files, with an owner-controlled component handing it an already restricted connection. Typing into an ordinary same-UID shell also grants owner-equivalent access. Defer bearer tokens until a transport needs independent redemption and defines reconnect, expiry, and revocation. [RPC trust] · [Attach handshake] |
| **Fail-closed negotiation** | Establish protocol support **before** session lookup, creation, PTY resize, or output. A `Ready` response should confirm the effective mode. A `Ready` echo alone arrives too late because a legacy daemon can ignore the new hello field and already have changed shared state. The cited compatibility test covers `Mouse`, so add an explicit legacy-daemon handshake test. [Protocol tests] · [Handshake order] |
| **Scope and privacy** | Use a dedicated whole session as the first sharing scope once the trust model is set. It fits the existing global focus and zoom model, and the guest protocol can exclude generic RPC. Drop compositor-only `pane.set_private`. Hidden cells can still be exposed through scrollback, selection, images, cursor state, titles, status chrome, and queued frames. If a concrete workflow needs one pane, give that pane a separate current-screen view with its own state and static chrome. [Focus sync] · [Zoom] · [Copy overlay] |
| **Approvals and handoff** | Drop Issue C. OSC 7501 carries program-reported status, and the proposed reply fields fail today’s grammar. Extending the grammar would let PTY output specify privileged input. Generation and pane-incarnation checks help detect stale cards, but the foreground process can change before queued bytes are consumed. A future approval integration should use an authenticated application endpoint that atomically consumes a single-use request for a typed decision. The client currently discards `Notice`. Any later keyboard handoff needs an explicit lease checked at input admission, independent of sizing, with paste and mouse cleanup on transfer. [OSC grammar] · [PTY writes] · [Notice handler] |

## Issue order and acceptance criteria

1. **#190 PR A owns the registry, size arbitration, and pins.** Use one client ID across lifecycle events and input bookkeeping. Track whether each connection votes and update its activity from committed pane input. Copy-mode keys, help, and rejected writes leave the size vote unchanged. Preserve explicit `pane.set_size` pins. The elected driver determines PTY size. [#190](https://github.com/indrasvat/shux/issues/190) · [Client event ID] · [Current attach ID]
2. **#191 ships local read-only attach independently of sharing.** Keep `--unpin`, attach/detach events, and registry-backed `session list` activity. Preserve local help, copy, selection, and yank. Explicitly reject `Paste`, PTY input and app mouse forwarding, shared focus and layout changes, PTY resize, and persistent onboarding writes. A viewer’s resize updates its viewport without voting on PTY size. Verify legacy rejection before any shared-state changes. [#191](https://github.com/indrasvat/shux/issues/191) · [Client frames] · [Mouse focus path]
3. **Add `client.list` and `client.detach` on that registry.** Make detach work against a blocked writer. Bound queued bytes and write time, interrupt an in-flight write on cancellation, and discard pending frames on disconnect. Test both healthy-client and PTY progress while one reader is blocked, then verify prompt detach of that reader. Defer live role changes and presence UI until an operator workflow needs them. Keep attribution to metadata and keep keystroke bytes out of recordings and events. [Writer] · [Teardown] · [Recorder]

## Independent work

- **Guest terminal effects need a server-owned allowlist.** Raw escape probes cover only part of the surface. Shux can re-emit hyperlinks, cursor color and shape, and kitty graphics, and generate clipboard writes on yank. Pane titles can also reappear as rendered text. For a future guest surface, start with static chrome and disable graphics, hyperlinks, clipboard writes, and pane-controlled cursor styling. Test decoded frames and rendered effects. [Renderer] · [Kitty emission] · [Yank]
- **Cursor-move elision is a standalone performance change.** The reported **9.23×** is a baseline stream-to-visible-character ratio for one workload. Savings still need measurement. Start with contiguous same-row runs after a known single-column printable ASCII cell, with explicit positioning around gaps, wrap, uncertain widths, and frame boundaries. Measure ANSI and framed bytes separately. Verify on a real outer terminal because `render.rs` is outside `VT_PATHS`. [Renderer] · [Gate paths]
- **Keep TCP outside this proposal.** The shipped daemon disables it, the library can bind it, and the PRD documents opt-in loopback. Any removal or authentication change deserves its own product and library decision. [Daemon configuration] · [PRD]
