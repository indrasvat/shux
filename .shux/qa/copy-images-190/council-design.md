Ārya, B2 should freeze the **pane viewport the client actually displayed**, use one resolved copy slice for rendering and selection, and keep image placement shared between live Kitty output and composed snapshots. The supplied reviews agree on that direction. The design below resolves their differences against the reviewed base, `main` at `444b6ba` after B1. ## Copy mode

1. **Enter from the displayed frame.** Add a backward-compatible `frame: Option<u64>` to keyboard copy entry, populated by the client’s displayed-frame counter. Resolve it through `ShownFrames`. For wheel entry, use the event’s frame to capture the hit pane and its viewport before changing focus. Unstamped clients can use the latest sent viewport. If an explicit stamp has expired or its pane is gone, decline entry, suppress the success notice, and request forced frame publication. A render pulse alone can leave an idle client without a replacement frame. Compute wheel scrollback headroom from the captured slice, including grid rows above it. [Attach input and frame handling](/private/tmp/b2-design/crates/shux/src/attach.rs:669)

2. **Keep modal state bound to its pane and resolve one slice.** Keep modal-specific geometry separate from the state reused by ordinary mouse selection. Store the entry viewport as the baseline and track the current presented top row and column offset separately. At entry, the top is history length plus the captured grid row offset. Use the captured shown dimensions, read through `presented_row`, and apply B1’s wide-cell edge rules against each row’s actual length. Use that mapping for text, highlighting, the copy cursor, hit-testing, and both yank paths. Leave surplus cells to the compositor. This freezes the viewport mapping while the application continues to produce output. [Copy slice](/private/tmp/b2-design/crates/shux-ui/src/copy_mode.rs:538) · [Presented rows](/private/tmp/b2-design/crates/shux-vt/src/lib.rs:1243)

3. **Record the modal mapping with the numbered frame.** Extend `ShownFrames` with the modal pane ID, shown geometry, and presented row origin. The render loop’s overlay stamp can still drive redraws, but input handlers need the mapping in the frame record. Route modal pointer gestures through their stamped frame. Resolve keyboard yank from the current modal selection and validate its source mapping before extraction. Publish a numbered frame when the mapping changes even if the cell bytes match. Exit on focus change, pane loss, or a resize that invalidates the mapping. Cancel selections whose source rows are evicted or remapped. Re-entry while already modal is a no-op. On exit, redraw from fresh live geometry. [Overlay stamp](/private/tmp/b2-design/crates/shux/src/attach.rs:57) · [Frame publication](/private/tmp/b2-design/crates/shux/src/attach.rs:2502)

4. **Search whole presented rows and reveal the complete hit.** Map UTF-8 byte ranges to their owning grid cells, including a wide glyph’s continuation. Filter matches by **start column** so backward search and same-row wrap can find a match that crosses the cursor column. `/`, `?`, `n`, and `N` start from the projected copy cursor. Pan only as far as needed to show the whole match, or its leading cell when the match exceeds the view width. Allow the modal horizontal range to reach matches in history rows wider than the current grid. Keep selection endpoints in source coordinates so a pan preserves the selected range, and clip only the visible highlight. Keep `h`/`l` and arrow movement within the shown slice. [Search and cursor handling](/private/tmp/b2-design/crates/shux-ui/src/copy_mode.rs:323)

5. **Give vertical navigation explicit bounds.** Let search reveal rows above or below the entry slice. Scroll commands move from the current top toward the corresponding end of the presented buffer. `G` goes to the bottom of that buffer. Wheel-only copy mode exits when scrolling back down to the entry slice. Starting a search makes the session explicit, so subsequent wheel input follows ordinary modal scrolling. Put a focused hit above the hint row where the geometry permits.

## Image clipping

- **Share signed placement geometry.** Make `ComposedPlacement.col` signed and compute `rect.x + image_col - col_offset` in the existing shared resolver. Clip against the pane’s shown-cell rectangle in both axes. A placement in a right-hand split can be left of its pane while its frame column is still positive. In copy mode, use the modal horizontal origin even while showing history. For vertical placement, follow the modal slice when it lies within the grid and retain the frozen grid baseline when it includes history. Historical image replay stays outside B2. [Shared placement resolver](/private/tmp/b2-design/crates/shux-ui/src/composed.rs:217)
- **Reuse Kitty image data across viewport changes.** Intersect the fitted image with the pane clip, position CUP at the clipped top-left, and map the visible pixel interval into the application crop with floor rounding at the start and ceil rounding at the end. Send `a=p` with the same host ID for geometry-only changes. Preserve omission of `x=` when it is zero. Match placements before visibility filtering using pane ID plus a stable placement ID in a `shux-ui` wrapper, with the existing image identity check. This survives both sibling clipping and removal of an earlier placement. For B2, retain conservative frame-budget accounting and transmit-before-delete ordering. A fully clipped placement still retires, so returning after deletion requires transmission. [Kitty emitter](/private/tmp/b2-design/crates/shux-ui/src/kitty_emit.rs:71)
- **Clip raster output before decode.** Give `blit` a signed origin and a four-sided pixel clip. Use the rasterizer’s actual cell metrics and saturating coordinate arithmetic. Reject an empty intersection before charging decode budget. Preserve crop-then-resize order and sample from both `skip_x` and `skip_y`. [Raster blit](/private/tmp/b2-design/crates/shux-raster/src/lib.rs:533)
